# GIT-012 — Complete the End-to-End GitHub Workflow

## Objective

Complete a reviewable engineering exercise that demonstrates **complete the end-to-end github workflow** and explain the decisions you made.

## Context

This is task 12 in the Git and GitHub phase. It builds one durable skill inside the same GitHub workflow used for product work: issue, branch, implementation, validation, pull request, review, and revision.

## What You Need to Learn

- The core concepts behind complete the end-to-end github workflow.
- How to recognize success and failure using observable evidence.
- How this skill affects users, maintainers, and adjacent systems.

## Requirements

1. Create or update the task artifact under `practice/git-lab/git-012/`; do not scatter unrelated changes across the repository.
2. Add a short `README.md` in that task artifact containing the problem, your plan, commands used, and result.
3. Produce the smallest working example or analysis that demonstrates complete the end-to-end github workflow.
4. Cover one normal case, one edge case, and one failure case relevant to the task.
5. Record at least one tradeoff or alternative you considered.
6. Keep the change reproducible by another intern from a clean checkout.

## Files / Folders

- Primary workspace: `practice/git-lab/git-012/`
- Evidence: `practice/git-lab/git-012/README.md`
- Tests or checks: colocate with the implementation using the project convention.

## Implementation Guidance

Follow the named steps, stopping to explain each result in your own words.

Start with a failing observation or explicit expected outcome. Work in small increments and keep command output needed for review concise.

## Restrictions

Use a disposable practice branch and never rewrite shared history.

- Do not commit generated dependencies, build output, credentials, tokens, or personal data.
- Do not change unrelated files or weaken an existing check to make validation pass.
